## 4. AI visibility

The `seo-geo` Task-tool agent ran a rigorous, controlled recheck of the standing GPTBot finding (~140 requests across 6 spaced rounds, 20s apart, OAI-SearchBot sent first each pair as a control). **Correction to the standing finding, now confirmed rather than hypothesized:** GPTBot is throttled but not fully blocked — 3/18 (~17%) of its GETs succeeded, versus 11/13 (~85%) for OAI-SearchBot and 7/9 (~78%) for a plain Chrome UA on identical paths. GPTBot still failed 4/5 even completely alone at 30s spacing, ruling out the failures being an artifact of concurrent/rapid testing. `HEAD` still returns 200 for GPTBot; `robots.txt` still allows it — this is edge-level throttling (`server: hcdn`), not a robots directive. **Impact is narrower than the raw number suggests**: GPTBot is OpenAI's *training* crawler only. OAI-SearchBot — the crawler that actually governs ChatGPT Search citability — was clean 6/6. So this costs training-corpus inclusion, not live citation visibility. There is also a separate, UA-agnostic per-IP burst limiter that affects any rapid-fire UA (including plain Chrome) — this is what earlier/faster probing runs (including this session's own heavy `curl` testing against the live site) were likely tripping and over-generalizing from.

GEO/AI-citability readiness scored 60/100. Strongest asset: `llms.txt` is present and high quality (NAP, prices, all 15 guides, well under the ideal size). Weakest: citability structure — only ~5 of 74 page sections sitewide fall in the 134–167-word self-contained-answer band AI systems tend to lift verbatim; `/about` is the worst single page, with 675 words under exactly one H1 and zero H2s, meaning there is no section boundary for any retrieval system to chunk on. No YouTube, Reddit, Wikipedia, or LinkedIn presence — YouTube specifically is flagged as the single strongest citation correlate in the agent's model (~0.74) and is entirely absent. Full findings: `seo-reports/mosaichostels.com-audit/findings/geo.md`.

## 6. Fixed this week

All fixes verified against `verify.sh` (PASS) and cross-confirmed by 2+ independent audit agents before being applied, per the priority formula `impact × confidence ÷ effort`:

1. **Homepage H1/H2 text-concatenation bug** (`index.html`) — `<br>` with no preceding space caused extracted text to read "Varanasinear Assi Ghat" and "ThanaPlace to Sleep." Root-caused and confirmed independently by the drift and content-quality agents. Fixed by adding the missing space.
2. **Stale sitemap/llms.txt entry** (`sitemap.xml`, `sitemap-images.xml`, `llms.txt`) — `/blog/top-7-experiences-varanasi-traveler/` 301-redirects live (confirmed via `curl`) but was still listed in all three files, misdirecting crawlers and AI ingestion. Removed the entry from all three; the redirect's destination was already correctly listed.
3. **Homepage meta description echoed the title verbatim** (`index.html`) — flagged by the content-quality agent as a templating defect that duplicates the SERP snippet. Rewritten to lead with the distinct "2-minute walk from Assi Ghat" value proposition, reusing only facts already stated elsewhere on the page (no new claims).
4. **`aggregateRating` (4.8/427) had no visible, sourced on-page counterpart** — the single most cross-confirmed finding this run (5 independent audits: seo-local, seo-schema, seo-sxo, seo-content, plus the Google-API cross-check flagged the adjacent canonical issue). Added a "4.8 ★ Google Rating (427)" stat card linking to the same Google Maps listing already used in the schema's `hasMap`, on `index.html` and `about.html` — this makes the schema's number match a real, visible, sourced statistic rather than existing only in markup. `book-now.html` carries the same schema field but was left unfixed this run: its layout sits close to the live booking widget, which is explicitly out of scope to touch.
5. **`blog/post.html` client-side-render fallback never clears its default `noindex`** — a dormant landmine (all 15 current posts have static builds, so this path never fires today) that would permanently noindex any future post added without the static-build step. Fixed the success path to set `index, follow` once a post actually renders.
6. **`things-to-do-varanasi-local-guide` — the most-consolidated blog URL — had neither a Summary block nor FAQPage schema**, the only post among 15 missing both. Added both (source markdown and the live static HTML), sourcing every fact and Q&A directly from the post's own existing content — no new claims.
7. **Dead IndexNow placeholder leftovers** (`.htaccess` header, `.well-known/indexnow-key.txt`) — a literal `"indexnow-key"` placeholder string was being served in a live response header, and a placeholder file sat in `.well-known/`. The real, working IndexNow key lives at `/140ef5ae933ea27ef5ec39a4c06690e1.txt` (verified live) — removed both dead artifacts.
8. **Two-hop HTTP→HTTPS→www redirect** (`.htaccess`) — bare-apex HTTP requests bounced through an intermediate hop before reaching the canonical `https://www.` URL. Collapsed to a single-hop rule; verified the rule logic covers all four host/scheme combinations correctly (could not test live — deploy is pending, see below).
9. **Orphaned duplicate `blog.html`** — a dead, unlinked, un-referenced duplicate of `blog/index.html` (confirmed via a repo-wide reference search). Deleted.

10. **`aggregateRating` visibility gap on `book-now.html`** (deferred earlier in this same run, revisited on request) — added the same "4.8 ★ Google Rating (427 reviews)" line, but placed it in `.page-hero-content`, above and outside `#bookingWidget` entirely — no booking-flow markup or JS touched.
11. **`/about` mobile horizontal overflow** (`styles/global.css`), found by the retried seo-visual audit (§2b) — `.team-head .section-title` had no responsive override and stayed at 48px on every viewport, overflowing the "Great Experience" heading 16px past the mobile edge. Added matching `@media(max-width:1024px)`/`@media(max-width:767px)` overrides (36px/26px, same values the generic `.section-title` rule already uses everywhere else) so this heading now shrinks like every other section title on the site. Verified locally: `document.documentElement.scrollWidth` now equals `clientWidth` (375=375) at 375px, was 391 vs 375 before. Bumped `global.css?v=` from `20260913` to `20260928` across all 23 HTML files so the CDN/browser cache picks up the fix on next deploy (`.htaccess` caches CSS 30 days immutable).
